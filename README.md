# 毛孩找家｜寵物領養互動網站

溫暖奶油色的 Vibe Coding 課堂作品，提供寵物瀏覽、搜尋篩選、詳細介紹、收藏與生活習慣配對測驗。

## 開啟方式

下載根目錄的 `index.html`，用 Chrome、Edge 或 Safari 開啟。手機建議使用 GitHub Pages 正式網址；檔案 App 的預覽可能不執行互動程式。

## GitHub Pages 發布

在本儲存庫的 Settings → Pages，選擇 Deploy from a branch，分支 main、資料夾 /(root)，按 Save。以 Pages 設定頁顯示的 Visit site 網址為準。

## 規格書

毛孩找家｜寵物領養互動網站規格書 v1.1

一、主題與目的
製作一個溫暖奶油色風格的寵物領養互動網站，讓使用者瀏覽毛孩、依需求篩選，並收藏感興趣的寵物。核心目標是讓「認識、挑選、收藏」的流程容易理解與操作。

二、目標使用者
有意領養貓狗，希望先了解寵物年齡、性別、體型、所在地及個性的使用者。

三、資料範圍
使用 8 隻虛構寵物作為示範資料：4 隻狗、4 隻貓。
寵物名字：米米、橘子、豆豆、奶茶、阿福、芝麻、小白、布丁。
每筆資料包含固定識別碼、名字、種類、年齡、性別、體型、所在地、個性標籤、介紹、照顧需求及內嵌示意插畫。
所在地涵蓋台北市、新北市、新竹市、台中市、台南市、高雄市；體型分小型、中型、大型。
頁尾及詳細介紹均說明資料為虛構示範，不接受真實領養申請。

四、畫面設計
使用奶油色背景、陶土橘主色、鼠尾草綠點綴及圓角卡片。
頂部放置網站名稱、毛孩列表入口、領養前提醒入口與收藏按鈕。
首頁介紹區呈現「下一個家，從一次相遇開始」及貓狗插畫。
下方先呈現生活配對測驗入口，再依序呈現搜尋篩選區、結果數量、寵物卡片及領養前的時間、空間與長期承諾提醒。
桌面寵物卡片採四欄，較窄畫面兩欄，手機一欄。

五、功能規格與驗收方式
1. 瀏覽寵物
開啟頁面後顯示 8 張卡片，每張包含示意插畫、名字、性別、年齡、體型、所在地及個性標籤。

2. 種類篩選
可切換全部毛孩、狗狗、貓咪；顯示目前選取狀態。只有種類篩選時，狗狗和貓咪各顯示 4 隻。

3. 所在地與體型篩選
選擇地區及體型後立即更新結果，可與種類、搜尋詞一起使用；所有選取條件必須同時符合。
驗收例：選擇狗狗、新北市及中型，顯示小白。

4. 關鍵字搜尋
輸入文字後立即更新卡片與數量，也可點「搜尋」或使用鍵盤搜尋鍵送出。可搜尋名字、個性、所在地及介紹文字；支援貓咪／狗狗及英文 cat／dog，「臺」與「台」視為相同文字。搜尋會忽略前後空白，多個空白分隔的搜尋詞需全部符合。
驗收例：搜尋「親人」顯示米米、阿福、小白；搜尋「親人 新竹市」只顯示米米。

5. 重設篩選
清空搜尋詞、所在地、體型與種類，恢復當前清單的所有資料。在收藏頁重設時仍保留收藏頁模式。

6. 詳細介紹
點擊卡片的「認識」按鈕，開啟詳細介紹視窗，顯示該毛孩的插畫、資訊、個性、介紹及照顧需求。
可在視窗內收藏或取消收藏，並可按關閉按鈕、Esc 或點擊視窗外部返回。採原生 dialog 元素；鍵盤焦點與行動裝置操作仍需以瀏覽器實際驗收。

7. 收藏與取消收藏
點擊卡片愛心可收藏，再次點擊可取消。愛心狀態與頂部收藏數量同步更新；卡片和詳細介紹使用同一份收藏資料。

8. 我的收藏
點擊頂部按鈕切換收藏清單，進入時清空先前的篩選；收藏頁也能搜尋與篩選。點擊「回到全部毛孩」返回所有毛孩。
取消最後一筆收藏時顯示空收藏提示及返回瀏覽按鈕。

9. 保存收藏
以 localStorage 保存收藏識別碼。同一瀏覽器及網站來源重新整理後，應恢復收藏；不同裝置與瀏覽器不會同步，清除網站資料會移除收藏。
瀏覽器禁止或無法寫入儲存資料時，仍允許本次頁面內收藏並顯示限制提示。損壞或不合法的收藏資料不應造成頁面停止運作。

10. 空結果提示
沒有符合條件的資料時，顯示說明與重設按鈕，不留空白畫面。

11. 生活習慣配對小測驗
首頁提供「做個小測驗」按鈕，導覽列提供「生活配對」入口。
採逐題作答，共 5 題，每題 3 個單選選項：
- 種類：貓狗都喜歡／只想認識狗／只想認識貓。
- 每日專心陪伴與活動時間：約 30–60 分鐘／約 1–2 小時／約 2 小時以上。
- 居家氛圍：安靜規律／一般居家活動／熱鬧且活動較多。
- 互動偏好：常常互動／各自自在／兩種都可以。
- 願意陪伴的節奏：穩定成犬成貓／慢慢建立信任／陪年輕毛孩成長。

顯示題目進度，未選答案時不能前進；可返回上一題，原答案保留。
完成後從現有 8 隻虛構毛孩中推薦最多 3 隻，說明推薦理由與需要再了解的照顧需求。
只選貓或狗時，結果必須符合該種類；不受瀏覽列表的搜尋、地區、體型或收藏篩選影響。
結果頁可查看詳情、收藏、取消收藏、修改答案及重新測驗。收藏與原有列表共用同一份資料。
沒有符合程度接近的毛孩時，顯示無配對提示，提供修改答案與瀏覽全部毛孩的操作。
測驗答案只存於本次頁面記憶體，不上傳、不寫入 localStorage，重新整理後從介紹頁開始。

先依種類硬性篩選，其餘依下列規則累計內部排序分數：
- 活動節奏：完全一致 +4，差一級 +2，差兩級 +0。
- 居家氛圍：一致 +3；一方為一般活動、另一方不同時 +1；其餘 +0。
- 互動方式：一致 +3；回答不限時 +1；其餘 +0。
- 生活／適應節奏：一致 +2；其餘 +0。
- 分數達 6 才列入推薦，按分數排序，最多 3 隻；同分依原資料順序保持穩定。
畫面不顯示契合百分比，也不把分數當成真實領養評估。
若毛孩較活潑、偏好安靜環境、較年輕或屬大型犬，會依答案或資料顯示進一步確認照顧需求的提示。

驗收例：
- 貓／30–60 分鐘／安靜／自在互動／慢慢建立信任：奶茶優先，其次芝麻。
- 狗／2 小時以上／熱鬧／親近／穩定：豆豆優先。
- 貓／2 小時以上／熱鬧／自在互動／慢慢建立信任：顯示目前沒有接近條件的毛孩。

六、技術與交付形式
最終網站為單一 index.html，HTML、CSS、JavaScript、寵物資料與 SVG 插畫全部內嵌。
不使用外部圖片、字型服務、套件、後端、登入系統或外部 API。
可下載後以現代瀏覽器開啟；正式公開版本以 GitHub Pages 網址為準。
表單具有文字標籤、按鈕具有可讀名稱與收藏狀態，並提供鍵盤焦點樣式及減少動畫設定。

七、已發生的 AI 討論與調整紀錄
第一輪：使用者提出寵物領養網站主題，AI 協助整理瀏覽、篩選、搜尋、詳情及收藏的初稿規格。
第二輪：使用者選定「溫暖奶油色＋瀏覽、篩選、收藏」，據此確立第一版範圍與視覺方向。
第三輪：AI 製作單一 HTML，將示意插畫內嵌，避免依賴額外圖片檔；補上空搜尋結果、空收藏及儲存失敗提示。
第四輪：進行 HTML、JavaScript 語法與互動邏輯檢查，涵蓋多條件篩選、收藏狀態、資料恢復及無法儲存等情境。
第五輪：使用者回報手機首頁插畫與搜尋異常。發現網站尚未發布，手機檔案預覽為可能原因。將首頁插畫改為直接內嵌 HTML 並指定響應式尺寸、移除巢狀 SVG 視窗，增加搜尋按鈕、中文輸入完成事件及搜尋同義詞；補上檔案預覽提示，31 項程式邏輯與事件檢查通過。手機實際效果仍待正式網址驗收。

第六輪：使用者要求加入生活習慣配對小測驗。新增 5 題、進度、單選驗證、回上一題、推薦理由、低符合程度提示、修改答案與重新測驗，並與原有詳情和收藏共用資料。45 項邏輯與事件檢查通過，包含全部 243 種答案組合；配對理由以虛構資料設定為依據。
